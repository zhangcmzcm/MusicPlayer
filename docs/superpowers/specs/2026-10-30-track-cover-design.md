# 歌曲封面读取接口设计

日期：2026-10-30

状态：对话设计已确认，待书面规格审阅。

基线：main @ eba5709。

## 1. 目标与范围

本次只实现 `GET /api/v1/tracks/{trackId}/cover`。地址与已有歌曲详情的 `cover.url` 完全一致，鉴权后从私有 S3/MinIO 流式返回原始封面，不重定向到对象存储，不生成预签名 URL。

覆盖权限、可选封面、存储对象缺失、元信息一致性、条件请求、流资源关闭、OpenAPI、中文 API 文档和真实容器测试。不实现上传、替换封面、缩略图、图片转换、音频播放、认证状态缓存或其他任务书条目。

不新增依赖或数据库迁移，不改动已执行的迁移。不顺手重构现有存储命名或认证响应。

## 2. 方案比较及确认结果

读取方式沿用已确认的后端代理方案。私有存储不直接暴露给客户端，复用已有 `AudioStorage` 抽象；其名称虽包含 Audio，但现有导入流程已经使用它保存封面。

无封面有两种可选方案：返回 404，由前端显示默认图；或后端维护并返回默认图。本次选择前者，不增加默认图片资源。

缓存比较：

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 私有缓存，每次验证（选定） | 304 节省图片传输，每次验证权限与对象状态 | 仍需认证、数据库和存储元信息请求 |
| no-store | 实现简单 | 每次完整传输 |
| 短期私有缓存 | 减少请求量 | 缓存期内可能继续使用归档或权限撤销前的图片 |

缓存不能撤回客户端已经保存或展示的图片。本设计保证每次服务端验证都执行当前权限检查，不承诺撤回客户端已取得的数据。

## 3. 请求与权限

- Method：GET。
- Path：`/api/v1/tracks/{trackId}/cover`。
- 请求体：无。
- `trackId`：沿用 Long，范围 1 至 9223372036854775807。零、负数、非整数、小数和溢出返回 400 VALIDATION_FAILED。
- 可选请求头：`If-None-Match`，用于 ETag 验证。
- 需要有效 Bearer JWT，沿用签名、issuer、audience、有效期、角色与 token version 校验。身份和角色只能来自验证后的认证上下文。

| 身份 | DRAFT | PUBLISHED | ARCHIVED |
| --- | --- | --- | --- |
| 未认证 | 401 | 401 | 401 |
| 已认证非管理员，含上传者本人 | 404 | 允许继续读取封面 | 404 |
| 以 ADMIN 角色登录的管理员 | 允许继续读取封面 | 允许继续读取封面 | 允许继续读取封面 |

管理员以 USER 角色登录时按普通用户处理。共享曲库不按上传者归属限制管理员访问。

必须先验证歌曲存在与可见性，之后才访问封面资产和对象存储。不存在或不可见统一抛出现有 TrackNotFoundException，响应为 404 TRACK_NOT_FOUND，不返回歌曲状态、上传者或封面信息。没有封面不影响歌曲详情接口的 cover=null 语义。

## 4. 成功响应

### 4.1 完整图片

无条件请求或 ETag 不匹配时返回 200，响应体为完整图片字节流。

| 响应头 | 值与规则 |
| --- | --- |
| Content-Type | 已验证的 image/jpeg、image/png 或 image/webp |
| Content-Length | 已验证的完整图片字节数 |
| ETag | 封面 SHA-256 的小写十六进制值，外加双引号，作为强标签 |
| Cache-Control | private, no-cache |
| Vary | 包含 Authorization，合并保留框架已有 Vary 项 |

不返回 bucket、对象键、原始文件名或凭据。摘要仅作为 ETag 使用，不增加摘要业务字段。保持项目已有安全响应头，包括 X-Content-Type-Options。

### 4.2 条件请求

按以下顺序处理：认证 → 歌曲可见性 → 封面资产检查 → 对象存储元信息及一致性检查 → If-None-Match 匹配。

匹配则返回 304，无响应体，携带同一 ETag、Cache-Control 和 Vary；不填写图片长度为 0，不读取图片内容流。不存在或不一致的对象即使标签匹配也不能返回 304。

支持 If-None-Match 的单标签、多标签、弱标签和通配符 `*`。GET 验证采用弱比较，即 `W/"摘要"` 可匹配当前 `"摘要"`；`*` 仅在有权访问且实际存在一致封面时匹配。无法识别的标签不能错误触发 304，按未匹配处理。使用框架合适的解析能力，不能仅按一个字符串等值比较。

本次不返回 Last-Modified，不实现 If-Modified-Since 或其他条件请求功能；时间条件不替代权限及对象检查。

### 4.3 Range 边界

本次不支持客户端图片字节范围。Range 被忽略；当正常响应应为 200 时返回完整图片，不返回 206、Content-Range 或声明 Accept-Ranges: bytes。If-None-Match 匹配时仍返回 304，不能因为存在 Range 而绕过条件验证。

现有存储实现可能以全长度 S3 Range 获取完整对象；这是内部读取方式，不意味着对客户端提供 Range 契约。音频播放的 Range 独立设计实现。

## 5. 资产与对象一致性

封面引用为空：404 COVER_NOT_FOUND。引用非空但资产记录不存在，或 kind 不是 COVER：500 INTERNAL_ERROR。数据库中的 MIME、大小和摘要必须有效；本地资产元信息非法也按内部一致性故障处理，不能直接写入响应头。

读取存储元信息，验证：

- MIME 与数据库一致且位于已支持的 JPEG、PNG、WebP 白名单。
- 大小为正数，且与数据库 sizeBytes 一致。
- sha256 为有效的 64 位十六进制值，忽略大小写与数据库摘要比较。

对象元信息缺失、格式无效或与数据库不一致返回 502 COVER_STORAGE_INCONSISTENT。现有 head() 对非法摘要抛出 IllegalArgumentException，实现时要在明确的存储读取边界转换，不能把所有编程异常笼统映射为 502。

本接口对比的是对象元信息，不是每次重新读取全图计算摘要，也不重新进行图片解码或魔数验证。继续依赖现有上传验证与对象不可原地修改的约束；未来替换封面应创建新资产和新对象。

元信息检查与后续内容读取之间可能发生删除。实际打开流时仍需处理 404、连接失败及可见的元信息变化；复用 read() 时其返回的元信息必须再次检查，不能无条件信任较早 head() 的结果。

304 的对象存在性判断以该次检查时刻为准；不通过长事务或对象锁保证响应后永远存在。歌曲状态也以本次授权快照为准，不在每个传输块重新查询数据库。

## 6. 错误契约

业务错误采用 RFC 9457 ProblemDetail、application/problem+json、稳定 code 与 `urn:problem:music:*` 类型。错误响应 Cache-Control 为 no-store，保留 traceId，不输出存储地址、SQL、堆栈或凭据。

| 场景 | HTTP | code |
| --- | --- | --- |
| 非法 trackId | 400 | VALIDATION_FAILED |
| 未提供认证 | 401 | UNAUTHORIZED |
| 认证必要声明非法 | 401 | INVALID_TOKEN |
| 用户不存在、Token 版本不符或登录角色已不被允许 | 401 | TOKEN_REVOKED |
| 歌曲不存在或不可见 | 404 | TRACK_NOT_FOUND |
| 歌曲无封面或存储对象已不存在 | 404 | COVER_NOT_FOUND |
| 数据库封面引用或资产元信息不一致 | 500 | INTERNAL_ERROR |
| 存储元信息缺失、无效或与数据库不一致 | 502 | COVER_STORAGE_INCONSISTENT |
| MinIO 连接、超时或服务故障 | 503 | MEDIA_STORAGE_UNAVAILABLE |
| 歌曲或封面数据库读取失败 | 503 | TRACK_STORE_UNAVAILABLE |
| 认证状态存储不可用 | 503 | AUTH_STATE_STORE_UNAVAILABLE |

JWT 签名、有效期等解码失败沿用既有资源服务器 401 与 WWW-Authenticate 行为，可能没有业务 ProblemDetail。统一认证响应属于任务书 O06，不在本次扩展。

现有 AudioObjectNotFoundException 的全局映射为 TRACK_NOT_FOUND，而且异常内容可能包含存储位置。封面 Service 必须在本操作边界转换成封面专用异常，向外返回 COVER_NOT_FOUND 和通用文案，不能直接让底层异常进入该全局处理器。不要改变其他接口现有异常含义。

新增封面缺失及存储不一致异常，并在现有 GlobalExceptionHandler 最小增加 404/502 映射；已有 500、503 等错误码继续复用。错误 no-store 只针对本接口落实，不借机修改全项目缓存规则。

## 7. 分层、事务与流生命周期

Controller 处理 HTTP 参数、条件请求及响应构造；Service 负责权限、数据库元信息、对象存储协调和一致性判断。Repository 仅访问数据库；对外服务返回明确的读取描述或结果，不返回 JPA Entity。

在 Service 层短只读事务内取得歌曲和封面资产所需快照，事务结束后再进行存储 HEAD、GET 和网络输出。不得通过包住整个流的事务保持数据库连接。

复用 AudioStorage 和 S3AudioStorage。若需要封面读取的最小扩展，必须保持现有音频及导入、删除接口行为，并补相应存储回归；不进行公共命名或结构重构。

图片采用固定大小缓冲区传输，不使用 readAllBytes、不将完整图片放入 byte[]，不落地持久化文件。HEAD 不创建内容流，304 不遗留流。实际打开内容流前校验可提前发现的故障；资源一经打开，正常完成、元信息校验失败、输出失败、客户端断开及关闭失败均有明确释放路径。避免在响应尚未开始执行时打开流后遗留在无人接管的异步任务中。

图片响应提交前可按上表生成错误，不能残留图片 Content-Length 或 ETag。响应提交后断流不能改成 JSON、修改状态码或自动重试追加图片；中止传输并关闭输入流，保留脱敏 traceId 日志。传输缓冲、超时及执行方式应受既有存储超时与应用资源配置约束，不创建无界线程。

## 9. 测试与完成标准

Controller 契约测试：正整数及非法 ID、未认证、200 图片内容/类型/长度、200/304 缓存头、多个 ETag/弱标签/通配符、未匹配和无效标签、无响应体的 304、Range 忽略、错误 ProblemDetail 和 no-store。

Service 单测：完整角色与状态矩阵，包括上传者本人、管理员以 USER 角色登录；权限失败时不查询封面或存储；无封面、悬空引用、错误 kind；大小/MIME/摘要逐项不一致；大小写摘要一致；数据库与存储故障；HEAD 与 GET 之间删除；304 不创建内容流；各出口的流关闭。

真实 MySQL、Redis、MinIO Testcontainers 集成测试：

- 签名 JWT 真实认证链，覆盖 token version 撤销与角色映射，不能只靠 mock 主体。
- 上传真实 JPEG/PNG/WebP 测试对象，核对返回字节、头部和 ETag。
- 对象缺失、元信息不一致及 MinIO 不可用，均不得被错误转换为 304。
- 重复请求与条件请求不修改歌曲、版本和资产。
- 图片读取和客户端断开/模拟输出失败的资源释放；提交前与提交后失败使用不同预期。真实 HTTP 验证必要的响应提交行为，不能只用返回值证明断流正确。
- 回归现有音频存储、导入与删除行为，不以 mock 代替真实存储集成验证。

最终执行：`$env:MINIO_INTEGRATION_TESTS = "true"; .\gradlew.bat check`。如实统计通过、失败、跳过；必要容器测试被跳过不能宣称完成。按 AGENTS.md 准备单接口审核材料，设计审核与代码审核分开记录。

## 10. 工程默认项与限制

本次不新增专用限流、Redis 封面缓存、CDN、缩略图、图片变换或时间条件请求。每次条件验证仍有认证查询、数据库读取和存储元信息读取成本；304 优化的是内容传输，不等于认证状态优化已经完成。

图片浏览如何携带 Bearer Token 由前端对接决定；可通过带 Authorization 的请求读取图片。不把 Token 放在图片 URL，不新增匿名读取、查询参数 Token 或 Cookie 登录机制。
