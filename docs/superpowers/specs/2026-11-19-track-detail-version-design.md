# 歌曲详情补充编辑版本号设计

日期：2026-11-19

状态：用户已确认方案 A，并于 2026-11-19 审阅同意书面设计；进入实现计划。

## 1. 问题与目标

现有 `PATCH /api/v1/tracks/{trackId}/draft` 要求客户端提交当前 `version`，以乐观锁防止并发修改相互覆盖。歌曲列表、详情和导入响应均没有提供版本号，导致客户端首次打开编辑页、重新进入编辑页或处理版本冲突时，无法取得有效的编辑前置条件。

本次唯一变更接口为 `GET /api/v1/tracks/{trackId}`：在歌曲详情中增加当前 `version`。客户端通过现有详情接口取得歌曲资料及对应版本，再调用既有草稿编辑接口。

核查基线为 `main @ f910219e23590e4dab6a32dd304a324faf24e3a7`。当前 `.gitignore` 的既有修改属于用户工作，不纳入本任务。

## 2. 已确认方案

用户已确认方案 A：扩展现有歌曲详情响应。该接口已有编辑需要的标题、艺术家、专辑、曲序、碟号和状态，增加一个字段即可补齐读取链路。

比较过的方案 B 是新增专用草稿读取接口，需要另行维护路由、权限及重复的字段映射。本次采用方案 A，符合项目单接口变更要求。

## 3. 响应契约

方法与路径：`GET /api/v1/tracks/{trackId}`。

成功响应继续使用 `200 OK`、`application/json` 和 `Cache-Control: no-store`。新增字段：

| 字段 | JSON 类型 | Java / OpenAPI 类型 | 可空性 | 说明 |
| --- | --- | --- | --- | --- |
| version | integer | Long / integer(int64) | 非空 | 当前歌曲的乐观锁版本号，范围 0 至 9223372036854775807 |

响应示例：

```json
{
  "id": 42,
  "title": "歌曲标题",
  "artistName": "艺术家",
  "albumName": "专辑名称",
  "durationMs": 245000,
  "trackNumber": 3,
  "discNumber": 1,
  "version": 2,
  "status": "DRAFT",
  "cover": null
}
```

`version` 从本次读取的同一个 `TrackEntity` 取得，与响应中的其他歌曲字段对应。返回实际持久化版本，不推测、生成或默认填充版本号。读取本身不会递增版本。

所有获授权的详情成功响应均包含该字段，覆盖 `DRAFT`、`PUBLISHED` 和 `ARCHIVED` 三种状态。版本号用于提交前置条件，不表示调用者具有修改权限；草稿编辑仍由既有接口校验管理员角色及 `DRAFT` 状态。

## 4. 认证、可见性与错误

沿用详情接口的有效 Bearer JWT 认证及现有权限矩阵：

| 调用者 | DRAFT | PUBLISHED | ARCHIVED |
| --- | --- | --- | --- |
| 未认证 | 401 | 401 | 401 |
| 已认证非管理员，含上传者本人 | 404 | 200 | 404 |
| 以 ADMIN 角色登录的管理员 | 200 | 200 | 200 |

管理员以 USER 角色登录时按非管理员处理。隐藏与不存在的歌曲继续统一返回 `404 TRACK_NOT_FOUND`，错误响应不返回歌曲版本。

沿用既有参数校验、ProblemDetail、稳定错误码及数据库故障处理。本次增加响应字段，不产生新的错误码或权限分支。

## 5. 客户端使用流程

1. 进入编辑页时请求歌曲详情，保存返回的可编辑字段、状态和 `version`。
2. 调用既有草稿 PATCH 时提交读取到的 `version`，并按原契约提交需要修改的字段。
3. 保存成功后使用 PATCH 响应中的新版本；重新进入页面时重新读取详情。
4. 收到 `409 TRACK_VERSION_CONFLICT` 时保留本人输入，重新读取详情，核对并合并修改后再使用新版本提交。版本冲突不能通过自动覆盖或本地递增版本绕过。

客户端必须保留 int64 整数精度。JavaScript 消费端可复用项目已有的无损 Long 解析方式，并在提交时按 JSON 整数保留精确值，不直接用可能丢失精度的 Number 转换。

前端 `docs/tasks/song-management.md` 已将版本读取列为 MGMT-03 的前置依赖，当前草稿编辑页尚未实现。本次交付后端读取契约及使用说明，供该独立前端任务接入。

更新 `docs/api/track/get-track-detail.md` 的响应示例、字段定义和编辑读取说明；在 `docs/api/track/update-track-draft.md` 中明确现有版本号的详情读取来源及冲突恢复流程。后者只补充既有编辑契约的文档链接，PATCH 生产行为保持现有契约。

数据模型已具有 `@Version` 和非空 BIGINT 列，本次无需数据库迁移、依赖、安全配置或额外数据库查询。列表及导入接口不在本次变更范围内。
