# 登录认证时间绑定部署说明

适用：现有POST /api/v1/auth/login的auth_time绑定及受保护请求的严格解析。不新增数据库迁移、配置项、依赖、会话表或HTTP接口。

## 能力与边界

- 实际凭据验证产生原始UTC认证时间，密码与邮箱验证码登录均支持；管理员Ticket和JWT显式继承。角色选择、后续查询、签发不刷新时间。
- JWT的iat表示签发，auth_time表示验证；未来refresh须继承后者。本次没有refresh、再次验证、邮箱变更接口，也不增加300秒业务门禁或REAUTHENTICATION_REQUIRED映射。
- 缺auth_time的旧JWT继续普通访问，版本撤销、角色、到期校验不变；存在但非法的时间401 INVALID_TOKEN，不能降级为旧JWT或用iat/now补齐。
- 认证链的内部上下文包含通过校验的时间和版本，不保留原Token，不进入公开DTO。
- 已完成的认证版本绑定加固仍必须成立。时间字段不允许旧验证、旧Ticket升级为数据库新版本；最后复核后可能签出旧版本Token，但后续受保护请求会拒绝。

## 时钟同步、验收与告警（设计NOTE-001）

本项目明确采用auth_time零未来时间容差。现有JWT对exp/nbf等声明的容差不变，但不能拿它放宽auth_time或未来300秒近期窗口。

所有登录签发、角色选择和受保护请求验证节点必须使用同步UTC时钟。发布前由部署环境的时间同步工具/现有外部监控验证并留存：

1. 每个节点的同步状态、可信时间源、观测时间与估计偏差；连续15分钟观测节点间估计偏差不超过100ms。
2. 节点间偏差超过100ms告警；超过500ms或失去同步时摘除异常节点的认证流量，排查并恢复同步后重新验收。不得静默改应用容差兜底。
3. 在实际流量拓扑下跨节点签发和验证新JWT，含整秒附近签发、管理员等待选择角色及旧JWT普通访问烟测；保留请求时间、脱敏trace标识和结果，不留Token/密码/票据原文。
4. 不允许只凭“时间同步服务进程运行中”判定合格；偏差采样必须覆盖全部认证节点及网络测量不确定性，不能只看平均值。

这些阈值是本项目运维风险控制目标，不是零误拒保证。任意正偏差都可能在秒边界造成拒绝：签发节点为01.010秒时auth_time截为01.000秒，验证节点为00.990秒，即使仅差20ms也会认为它在未来并返回INVALID_TOKEN。固定/可控时钟测试明确覆盖这一取舍，不以跳过测试或改宽限消除它。

NTP状态、偏差监控与告警由实际部署平台实现；本代码变更不安装时间同步软件、不新增监控依赖、不扩大Actuator暴露。代码测试与accepted不代替上述环境验收。异常时先修复/隔离节点，不能把无auth_time的Token或iat推算值伪装为新验证证据。

## JWT与Ticket兼容

- 不递增全站token_version、不强制撤销旧JWT，不重写JWT或数据库行。
- 新Ticket为精确五字段userId/maximumRole/loginType/tokenVersion/authTime，TTL仍300秒，原子发布、带类型和PTTL检查的一次性消费；authTime必须规范、非负、在Instant范围且不在未来。
- 旧四字段Ticket不补当前时间，新代码拒绝；旧代码也会拒绝五字段Ticket。安排受控切流、全实例升级并排空旧登录请求；短期票据失效用户需重新登录，不通过兼容缺字段绕过验证。
- key命名空间、随机Ticket与SHA-256派生方式不变。不清空整个Redis，不扫描/重写旧记录，不影响其他验证码或改密限流key。
- Redis消费/发布结果不确定仍503，可能已经写入或消费；不恢复凭据、不自动重试。角色、版本复核不变。
- 原auth-version-binding.md中的四字段描述是上一版本历史基线；本次Ticket格式以本文件为准，旧文档的版本安全和全实例升级要求继续有效。

## 显式旧式签发入口（设计NOTE-002）

旧三参issue已移除。显式issue(snapshot, role, loginType, authenticatedAt)只接受真实验证时间，null/非法/未来拒绝签发；不以now填缺。

issueLegacyWithoutAuthTime用于明确的旧式签发兼容，结果没有auth_time，不获得近期资格。当前生产登录没有该入口调用；测试保留旧JWT场景时显式使用此名称，不改成now。上线代码检查与交互登录测试必须确认实际路径只调用显式时间接口。未来实现refresh时不得用这个入口假装近期验证，也不得将旧会话版本升级为新数据库版本。

## 回滚

回滚到不支持auth_time的登录实现可能签出缺字段JWT，普通访问仍按既有规则处理，但不得继续宣告近期验证能力全站生效；停止依赖它的新敏感功能上线/放行，不能以iat兜底。新旧Ticket都可能因格式不兼容而失效，重新登录即可，不改写票据。

不得回滚到已知会将旧验证结果升级版本的登录代码；若确需回滚认证版本加固，必须同时停止改密等依赖该保证的上线流程。部署、切流、排空、时钟验收和回滚操作由部署方单独确认，本任务不自动操作生产环境。

## 验证记录

实施材料必须报告真实MySQL/Redis/BCrypt/JWT链路、原始JSON载荷类型矩阵、缺失iat防推算、不可变时间传递、旧JWT兼容和已撤销版本拒绝、五字段Ticket并发消费与旧四字段拒绝。测试夹具包含track调用适配，必须启用MINIO_INTEGRATION_TESTS=true执行完整cleanTest check，按本次XML报告通过/失败/错误/跳过。
