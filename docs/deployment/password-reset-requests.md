# 找回密码异步发码部署与恢复

## 依赖与配置

唯一公开入口POST /api/v1/users/password-reset-requests；后续重置确认接口不在本交付范围。无新表、迁移、依赖或Compose服务，不改变既有验证码用途或JWT策略。

要求单Redis实例、Redis≥7，支持TIME/PEXPIREAT/PEXPIRETIME及Lua。所有实例必须连接同一业务Redis数据库；不支持Cluster跨槽。应配置符合部署需求的Redis持久化/备份及容量策略；业务键不应被任意逐出。入队成功不构成永久投递保证，Redis丢失可能使已受理任务消失，应用不会从数据库恢复投递。

| 环境变量 | 默认 | 含义 |
| --- | --- | --- |
| PASSWORD_RESET_QUEUE_CAPACITY | 1000 | 全局未结束任务容量，所有实例使用一致配置 |
| PASSWORD_RESET_WORKER_CONCURRENCY | 4 | 每实例最多并发等待的发码任务及SMTP线程数 |
| PASSWORD_RESET_SEND_TIMEOUT | 20s | 单次发送等待上限，必须为1至2147483647毫秒内的正Duration |

容量/并发必须为正整数。SMTP来源沿用MAIL_*及app.mail.from；专用客户端复制设置与凭据，独立控制smtp/smtps连接/读/写超时，不修改其他邮件客户端。SMTP调试关闭，凭据不输出。单实例发送池无缓冲，无法取消的底层SMTP仍占物理线程，超时不会无限创建新线程。

生产后台默认自动启动；`app.password-reset.worker-auto-start`默认true，只有测试profile固定false，以免上下文中后台线程访问其他用例已停止的容器。测试显式驱动真实Processor或两个Lifecycle验证调度。若人工关闭生产自动启动，HTTP仍只按可靠入队返回202，任务可能在未处理前到期，不能把202当送达证明。

Redis TIME定义额度窗口、UTC日及300秒期限。应用/Redis时钟应同步，邮件UTC时间与Redis期限保持一致；进程间系统时钟不参与任务先后判断。后台每250ms尝试领取，每秒最多清理100个到期索引；每轮有界，积压导致暂时满载时可503，不驱逐未到期任务。

## 数据与并发语义

所有合法邮箱同限流/查询/入队/容量与格式，HTTP不等SMTP；不承诺数据库耗时完全一致。邮箱索引查询后Java精确核验，MySQL NO PAD下首尾含空格历史地址按无匹配处理，不扫描补找；大小写可匹配、重音等价不可误发。非规范历史数据若需支持，单独规划修复或查询策略，本功能不自动改库。

任务队列/指针、验证码、额度使用music:auth:password-reset独立命名空间。仅最新待处理申请可激活；先受理但慢查询晚入队的申请不能覆盖新申请，最新水位保留至原deadline。旧已领取任务仍占未结束槽至结束或原期限，旧排队任务被替换可释放。队列满503不部分覆盖原pending，不影响ACTIVE。

领取最多一次且归属固定，无租约接管或重投；进程崩溃在领取已发生时，任务等原deadline清理，其他实例不自动补发。无账户任务正常结束不发信；后来注册相同邮箱也不追认原申请。版本/邮箱/角色变动或删除使受理快照失效，普通登录/再次验证不递增版本。

任务无验证码明文，ACTIVE仅保存BCrypt摘要及账户/邮箱/版本/期限绑定，错误次数初始0。完整challengeId只回客户端，Redis保存SHA-256摘要；数据仍含投递邮箱及账户绑定，应作为敏感认证数据保护。任务在排队/处理阶段到期均不得激活，不延长期限。

## 未知结果与恢复

- HTTP扣额后DB/队列失败不退款；入队执行后丢回包503时可能已经有任务，不自动重试。客户端在冷却结束后可新申请。
- 领取结果未知：可能已领取，执行方不发信，也不重新领取同任务；原期限后释放容量。
- SMTP报错、超时、中断、执行器拒绝：本次终止，不自动重发、不激活新码，原ACTIVE保留本来期限。邮件可能实际投递且不可用，不能保证完全没有死码邮件。
- 明确发送成功后还需账户复核与原子激活；激活已执行但回包丢失时新ACTIVE可能已生效，不能恢复旧ACTIVE或清除可能成功的新码。
- 结束/清理回包未知：不重发、不删除新pending或ACTIVE；剩余任务索引依原deadline有界回收。
- 最终DB复核和Redis激活非原子，若期间改密/换邮箱，ACTIVE仍绑定原版本；未来确认接口必须重新核验并CAS，不能把ACTIVE存在当永久授权。
- 停机先停止领取并中断本地等待，后台线程受控结束，未确认的已领取任务不退回队列。进程重启不清额度、队列或水位。

不提供生产删键清额放行命令、公开查询/调试/恢复接口。无需用户原登录；主动带无效Token会沿用401/403或AUTH_STATE_STORE_UNAVAILABLE，正常不带Token即可申请。

## 观测与验证

通过受理traceId关联后台脱敏分类日志；不得输出邮箱/IP明文、完整申请标识、码/摘要、Token、密码、邮件正文或原始依赖异常链。保留health/info/metrics既有Actuator范围。日志不能作为向用户确认账户存在或发送成功的公开状态源。

使用真实MySQL8.4、Redis测试准入、队列、替换、到期、跨实例领取与故障注入；仅SMTP可控替换。最终完整回归：
